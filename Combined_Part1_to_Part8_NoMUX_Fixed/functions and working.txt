This document provides a comprehensive, function-by-function operational breakdown of the Line Follower Robot
firmware in the exact chronological order of execution, from power-on boot through sensor calibration, PID line
tracking, 90-degree turn recovery, and emergency safety mechanisms.

DETAILED FUNCTION BREAKDOWN IN ORDER OF EXECUTION
========================================================================================================================

------------------------------------------------------------------------------------------------------------------------
PHASE 1: BOOT & SYSTEM INITIALIZATION
------------------------------------------------------------------------------------------------------------------------

1. Function: setup()
   - File: Combined_Part1_to_Part8_NoMUX_Fixed.ino
   - When Executed: Exactly once when power is applied or the Arduino reset button is pressed.
   - Execution Sequence:
     Step 1.1: Initializes the hardware UART Serial port at 9600 Baud for communication, telemetry, and debugging.
     Step 1.2: Configures motor driver pins (D2, D4, D5, D6, D7, D8) as digital outputs.
     Step 1.3: Configures user input push buttons (Button 1 on Pin D11, Button 2 on Pin D12) with internal pull-up
               resistors (INPUT_PULLUP). Buttons are Active-LOW (read 0V when pressed).
     Step 1.4: Configures the on-board Status LED (Pin D13) as a digital output and ensures it starts turned OFF (LOW).
     Step 1.5: Calls motor(0, 0) to ensure the robot remains completely stationary at startup for safety.
     Step 1.6: Calls LoadCalibration() to retrieve previously saved sensor thresholds from non-volatile EEPROM.
     Step 1.7: Prints a control instructions guide to the Serial Monitor, alerting the user that the system is ready.

2. Function: LoadCalibration()
   - File: SensorCalibration.ino
   - When Executed: Called by setup() immediately after pin configuration.
   - What It Does:
     Step 2.1: Reads 24 bytes from Arduino EEPROM:
               - Addresses 0 to 7   : Stored midpoint thresholds (Reference_ADC[0..7])
               - Addresses 8 to 15  : Stored maximum readings (Max_ADC[0..7])
               - Addresses 16 to 23 : Stored minimum readings (Min_ADC[0..7])
     Step 2.2: Multiplies stored 8-bit bytes by 4 to reconstruct the full 10-bit ADC values (0 to 1023).
     Step 2.3: Validates each sensor channel individually:
               - An unwritten EEPROM cell reads 255 (255 * 4 = 1020). An unprogrammed/zeroed cell reads 0.
               - Checks that the recorded contrast (Max_ADC - Min_ADC) is at least 40 ADC counts.
               - If valid, stores the value in Reference_ADC[i].
               - If invalid or uncalibrated, applies the safe fallback threshold (500) for that channel.
     Step 2.4: Prints the loaded reference midpoints across all 8 sensors to Serial.

3. Function: motor(0, 0) [Initial Safe Halt]
   - File: motor.ino
   - When Executed: Inside setup() before entering loop().
   - What It Does: Pulls all directional lines (D2, D4, D7, D8) LOW and commands 0 PWM duty cycle to D5 and D6.
     This engages active electronic braking on both motor channels, preventing unintended creeping.

------------------------------------------------------------------------------------------------------------------------
PHASE 2: MAIN SUPERVISORY POLLING LOOP (IDLE STATE)
------------------------------------------------------------------------------------------------------------------------

4. Function: loop()
   - File: Combined_Part1_to_Part8_NoMUX_Fixed.ino
   - When Executed: Continuously repeats after setup() finishes.
   - What It Does: Acts as the primary task scheduler and user input dispatcher:
     - Continuously polls Button 2 (Pin D12) to see if auto-calibration is requested.
     - Continuously polls Button 1 (Pin D11) to see if PID tracking should be launched.
     - Every 500 ms, triggers an idle diagnostic stream to monitor hardware health.

5. Routine: Periodic Idle Telemetry & read_black_line()
   - File: Combined_Part1_to_Part8_NoMUX_Fixed.ino & read_sensor.ino
   - When Executed: Every 500 ms while the robot is idling and waiting for a button press.
   - What It Does:
     Step 5.1: Calls read_black_line() to sample all 8 analog inputs (A0 to A7).
     Step 5.2: Prints a formatted status string to the Serial Monitor:
               Example: [IDLE MONITOR] Btn1(D11): HIGH(1) | Btn2(D12): HIGH(1) | Bitmask: 00011000 | Active: 2 | Centroid Pos: 45.0
     Step 5.3: Why this is critical: If Button 1 is pressed, this monitor immediately reports PRESSED(0). If it stays
               at HIGH(1), the user immediately knows their physical wiring is loose, disconnected, or wired to the wrong pin.

------------------------------------------------------------------------------------------------------------------------
PHASE 3: AUTONOMOUS DYNAMIC AUTO-CALIBRATION WORKFLOW (BUTTON 2)
------------------------------------------------------------------------------------------------------------------------

6. Function: calibrateSensor()
   - File: SensorCalibration.ino
   - When Executed: When the user presses Button 2 (Pin D12) while in idle mode.
   - Execution Sequence:
     Step 6.1: Debounce & Release: Waits for the user to release Button 2 so hands are clear.
     Step 6.2: Turns ON the Status LED (Pin D13) to indicate calibration is in progress.
     Step 6.3: Initializes Search Envelopes: Sets all Max_ADC[i] = 0 and Min_ADC[i] = 1023.
     Step 6.4: Executes a 4-Stage Rotational Sweep across the track line:
               - Stage 1: Pivot Left  (rotationDirections = {-1,  1}) at 40% base speed (PWM 80).
               - Stage 2: Pivot Right (rotationDirections = { 1, -1}) at 40% base speed.
               - Stage 3: Continue Right (rotationDirections = { 1, -1}).
               - Stage 4: Pivot Left  (rotationDirections = {-1,  1}) to return to center.
     Step 6.5: During each stage, samples the 8 sensors 400 times (1600 total sweeps). On each sample, updates:
               - If sensorADC[i] > Max_ADC[i], Max_ADC[i] = sensorADC[i] (records dark line peak).
               - If sensorADC[i] < Min_ADC[i], Min_ADC[i] = sensorADC[i] (records light background minimum).
     Step 6.6: Stops motors between each sweep stage for 150ms to prevent mechanical overshoot.
     Step 6.7: Dynamic Midpoint Calculation: Computes Reference_ADC[i] = (Max_ADC[i] + Min_ADC[i]) / 2.
     Step 6.8: EEPROM Persistence: Divides values by 4 to map 0-1023 into 0-255, and writes them to EEPROM using
               EEPROM.update() (which only writes if changed, saving write cycles).
     Step 6.9: Prints Min, Mid, and Max values for all 8 sensors to Serial.
     Step 6.10: Turns OFF the Status LED, indicating calibration is finished.

------------------------------------------------------------------------------------------------------------------------
PHASE 4: HIGH-SPEED CLOSED-LOOP PID LINE TRACKING WORKFLOW (BUTTON 1)
------------------------------------------------------------------------------------------------------------------------

- Safety Launch Countdown:
  - When Button 1 (Pin D11) is pressed, the sketch verifies button release, prints a launch message, and blinks
    the Status LED 3 times over 1 second. This gives the operator time to remove their hand before full-speed drive.

7. Function: PID_Controller(base_speed, kp, kd)
   - File: PID_Controller.ino
   - When Executed: Repeated continuously inside the supervised tracking loop while Button 1 is active.
   - Internal Step-by-Step Operations:

   Step 7.1: Sensor Acquisition via read_black_line()
             - Samples analog pins A0 through A7 sequentially using the ATmega328P ADC.
             - Thresholding: Evaluates raw ADC against calibrated Reference_ADC[i].
             - Polarity Inversion (inverseON):
               * In Normal Mode (0): ADC > Threshold -> sensorDigital[i] = 1 (Black line on white).
               * In Inverted Mode (1): ADC <= Threshold -> sensorDigital[i] = 1 (White line on black).
             - Centroid Accumulator:
               * sumOnSensor = count of active sensors.
               * sensorWight = sum of (sensorDigital[i] * WeightValue[i]), where weights are {10, 20, 30, 40, 50, 60, 70, 80}.
             - Bitmask Synthesis: Packs states into bitSensor byte (S0 = MSB bit 7, S7 = LSB bit 0).

   Step 7.2: Centroid Position & Error Estimation
             - If sumOnSensor > 0:
               line_position = sensorWight / sumOnSensor (Exact center is 45.0).
               error = 45.0 - line_position.
               offTrackStartTime is reset to 0 (line is actively seen).
             - If sumOnSensor == 0:
               Line is lost. offTrackStartTime is stamped with millis() to begin safety timeout.

   Step 7.3: State Machine Pattern Matching
             - Analyzes bitSensor to detect sharp turn signatures:
               * Left turn signatures (0b11111000, 0b11110000, 0b11100000, 0b11000000) -> direction = "left".
               * Right turn signatures (0b00011111, 0b00001111, 0b00000111, 0b00000011) -> direction = "right".
               * Center & mild curve patterns (0b00011000, 0b00110000, 0b00001100, etc.) -> direction = "straight".
               (Crucial bugfix: Resetting direction to "straight" prevents sticky turns on subsequent gaps).

   Step 7.4: Turn Execution on Line Loss (bitSensor == 0)
             - If bitSensor is 0 and direction is NOT "straight", control branches to Phase 5.
             - If bitSensor is 0 and direction IS "straight", and offTrackStartTime > 350ms, motors brake (motor(0, 0))
               to prevent off-track runaway into walls.

   Step 7.5: Proportional-Derivative (PD) Steering Math
             - derivative = error - previous_error.
             - correction = (error * kp) + (derivative * kd).
             - left_motor_correction  = base_speed - correction.
             - right_motor_correction = base_speed + correction.
             - previous_error = error (stored for next cycle).

   Step 7.6: Motor Drive Command
             - Calls motor(left_motor_correction, right_motor_correction).

8. Function: motor(int LPWM, int RPWM)
   - File: motor.ino
   - When Executed: At the end of every PID iteration to actuate the DC gearmotors.
   - What It Does:
     Step 8.1: Clamps input speeds safely between -255 and +255 using constrain().
     Step 8.2: Left Motor Direction:
               - If LPWM > 0: Sets D2 (BIN1) HIGH, D4 (BIN2) LOW (Forward).
               - If LPWM < 0: Sets D2 (BIN1) LOW, D4 (BIN2) HIGH (Reverse).
               - If LPWM == 0: Sets D2 LOW, D4 LOW (Active Electronic Brake).
     Step 8.3: Right Motor Direction:
               - If RPWM > 0: Sets D7 (AIN1) HIGH, D8 (AIN2) LOW (Forward).
               - If RPWM < 0: Sets D7 (AIN1) LOW, D8 (AIN2) HIGH (Reverse).
               - If RPWM == 0: Sets D7 LOW, D8 LOW (Active Electronic Brake).
     Step 8.4: Applies PWM duty cycle via hardware Timer 0:
               - analogWrite(left_motor_speed, abs(LPWM)) on Pin D5.
               - analogWrite(right_motor_speed, abs(RPWM)) on Pin D6.

------------------------------------------------------------------------------------------------------------------------
PHASE 5: SHARP 90° TURN & INTERSECTION RECOVERY WORKFLOW
------------------------------------------------------------------------------------------------------------------------

When a sharp corner is reached, the robot drives over a wide turn footprint (e.g., 0b11111000) which sets direction
to "left" or "right". As soon as the robot leaves the corner vertex, all sensors momentarily see white (bitSensor == 0).

- Corner Alignment Creep:
  The robot drives straight forward at 60% base speed for delay_before_turn (80 ms) to align its physical drive axle
  directly over the vertex point before beginning rotation.

9. Function: turnRight(int L, int R)
   - File: Turns.ino
   - When Executed: Inside PID_Controller() when bitSensor == 0 and direction == "right".
   - What It Does:
     Step 9.1: Records turn start timestamp (startTurnTime = millis()).
     Step 9.2: Enters in-place spin pivot: Left wheel forward (+L), Right wheel backward (-R).
     Step 9.3: On every spin loop iteration, samples sensors via read_black_line().
     Step 9.4: Loop terminates immediately when center-left (S3) or center-right (S4) recaptures the line.
     Step 9.5: Safety Watchdog Timeout: If millis() - startTurnTime > 1500 ms (line not recaptured), the loop breaks
               automatically to prevent infinite spinning.
     Step 9.6: Commands motor(0, 0) to brake rotational inertia, resets direction = "straight", and returns to PID.

10. Function: turnLeft(int L, int R)
    - File: Turns.ino
    - When Executed: Inside PID_Controller() when bitSensor == 0 and direction == "left".
    - What It Does:
      Step 10.1: Records turn start timestamp (startTurnTime = millis()).
      Step 10.2: Enters in-place spin pivot: Left wheel backward (-L), Right wheel forward (+R).
      Step 10.3: On every spin loop iteration, samples sensors via read_black_line().
      Step 10.4: Loop terminates immediately when center-left (S3) or center-right (S4) recaptures the line.
      Step 10.5: Safety Watchdog Timeout: If millis() - startTurnTime > 1500 ms, loop breaks automatically.
      Step 10.6: Commands motor(0, 0) to brake, resets direction = "straight", and returns to PID.

------------------------------------------------------------------------------------------------------------------------
PHASE 6: SAFETY, BRAKING & FAIL-SAFE SYSTEMS
------------------------------------------------------------------------------------------------------------------------

- Emergency User Halt Breakout:
  - Inside the continuous PID loop in loop(), the condition if (digitalRead(button_calib) == LOW) is polled on every
    iteration.
  - If the user presses Button 2 at any point during line tracking, the robot executes:
    motor(0, 0); // Immediate active electronic brake
    digitalWrite(led, LOW);
    Serial.println(F("\n>>> [EMERGENCY HALT] PID Line Tracking Stopped by User (Button 2)."));
    break; // Exits the PID loop and returns cleanly to idle mode!

- Straight-Line Off-Track Safety Brake:
  - If the line is completely lost (sumOnSensor == 0) and direction == "straight" for more than 350 ms, the robot commands
    motor(0, 0) instead of speeding forward indefinitely.

11. Function: stop()
    - File: distance.ino
    - What It Does: Commands motor(0, 0) for an active electronic brake stop.

12. Function: hard_stop()
    - File: Turns.ino
    - What It Does: Cuts motor power and enters an infinite while(1) loop blinking the Status LED, indicating a critical halt.

------------------------------------------------------------------------------------------------------------------------
PHASE 7: DIAGNOSTIC & BENCH TESTING UTILITIES
------------------------------------------------------------------------------------------------------------------------

13. Function: sensor_value_test()
    - File: read_sensor.ino
    - What It Does: Continuously reads and prints raw 10-bit ADC values (0 to 1023) for all 8 pins (A0 to A7) in a tab-
      separated stream. Call this in setup() or loop() to inspect sensor height and optical contrast.

14. Function: Bit_Sensor_Show()
    - File: read_sensor.ino
    - What It Does: Continuously prints the 8-bit digital bitmask (e.g., 00011000) and computed centroid position. Call
      this to verify threshold crossing and sensor alignment.

15. Function: motor_test()
    - File: motor.ino
    - What It Does: Drives motors forward for 1.2s, reverse for 1.2s, right pivot for 1.0s, left pivot for 1.0s, and stops.
      Use this during chassis construction to verify motor lead polarities before placing on a track.

16. Function: distance(int cm)
    - File: distance.ino
    - What It Does: Drives forward for a calibrated time proportional to the benchmark ratio:
      run_time = (cm * test_time) / measured_distance, then brakes. Useful for traversing dashed track segments.
